# M1 — Identity & crypto core

**Goal:** a working, tested key hierarchy and a lock/unlock experience. No financial data
yet — this milestone is the foundation everything else trusts.

Read with: ADR-0002 (key hierarchy), `docs/SECURITY.md`.

## Scope

1. **`src/crypto` primitives** (`size:M`) — Argon2id KDF via `hash-wasm`, AES-256-GCM
   seal/open with AAD, ECDH P-256 key pair generation, HKDF, AES-KW wrap/unwrap.
   Known-answer test vectors committed in `src/crypto/__vectors__`.
2. **Identity & vault** (`size:M`) — create identity (keypair + wrapped private key),
   passphrase change, recovery kit generation (24-word code) and restore.
3. **Household & HDK** (`size:M`) — create household, generate HDK, wrap to self; invite
   flow producing a wrapped-key blob for a second member; accept-invite path.
4. **Auth** (`size:M`) — Better Auth with passkeys + email OTP, invite-only registration,
   session cookies (httpOnly, secure, SameSite=Lax), rate limiting.
5. **Lock/unlock UX** (`size:S`) — unlock screen, auto-lock timer, wipe keys from memory on
   lock, optional passkey PRF fast unlock with passphrase fallback.

## Acceptance

- Unit tests pass against committed vectors; round-trip seal/open with wrong key fails
  closed; wrong passphrase never yields a usable key.
- A second member can be invited and can decrypt a record created by the first.
- Recovery kit restores access on a fresh browser profile.
- Keys are absent from IndexedDB and from any network request (asserted in tests).
- `docs/api/CONTRACT.md` updated with the auth + key-wrap endpoints.

## Files this touches

`src/crypto/**`, `src/features/auth/**`, `src/db/schema.ts`, `src/server/auth.ts`,
`docs/api/CONTRACT.md`, ADR-0002 amendments if parameters change.

## Out of scope

Any financial record type, sync engine (M2), prices (M4). Resist the urge.
