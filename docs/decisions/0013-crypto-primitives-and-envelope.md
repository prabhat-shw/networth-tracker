# ADR-0013 — Crypto primitives, envelope format and test vectors

**Status:** Accepted · 2026-09-26 · refines [ADR-0002](0002-key-hierarchy-and-sharing.md)

## Context

ADR-0002 fixed the algorithms. Issue #3 implements them in `src/crypto/`. A few details had
to be decided before anything is encrypted for real, because the envelope and KDF inputs
become permanent once records exist.

## Decision

- **Record envelope (v1), bytes:** `[0x01][kidLen:u8][kid utf8][iv:12][ciphertext‖tag:16]`.
  The leading format byte allows a future v2; the key id (≤255 bytes) makes HDK rotation
  possible without a flag day. `seal` draws a fresh random 96-bit IV every call.
- **AAD = `recordId|version`** (UTF-8). A `recordId` containing `|` or a non-integer or
  negative version is rejected, so the AAD is unambiguous.
- **Fail closed, opaquely.** `open` throws one `DecryptError("decryption failed")` for every
  cause: wrong key, tampered AAD, IV, ciphertext, truncated or unknown-format envelope.
- **Unlock key = non-extractable AES-256-GCM** (not AES-KW). A PKCS#8 P-256 private key is
  not a multiple of 8 bytes, so AES-KW cannot wrap it; AES-GCM wraps it with integrity.
- **Passphrase is NFKC-normalised** before Argon2id, so the same passphrase typed on another
  keyboard or OS unlocks the vault.
- **KDF params travel with the output:** `{alg, memoryKiB, iterations, parallelism, salt}`
  with a 16-byte random salt; defaults m=64 MiB, t=3, p=1.
- **HDK wrap = ECDH P-256 → HKDF-SHA-256 → non-extractable AES-KW key.** The raw shared secret
  and HKDF output are zeroed after import. Salt/info strings are fixed in #5.
- **Only public keys are exported** (raw 65-byte SEC1). Private keys and the HDK are
  extractable solely so WebCrypto can wrap them.
- **Known-answer vectors are copied from published sources, not generated by us:** PHC
  `argon2` reference `test.c`, Wycheproof AES-GCM, RFC 5869 A.1, RFC 3394 §4.6,
  RFC 5903 §8.1. They live in `src/crypto/__vectors__/kat.json`.

## Consequences

- Changing any of the above after real data exists needs a new envelope/format version.
- JS cannot guarantee memory wiping; zeroing buffers is best effort. Keys are kept as
  non-extractable `CryptoKey`s wherever WebCrypto allows it.
- `hash-wasm` becomes a runtime dependency (WASM Argon2id; ~0.5 s per derive at defaults).
